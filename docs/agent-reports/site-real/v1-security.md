## Checked and fine
- Uploads: the read is capped at 10 MB + 1 (site_build.py:244). The real format comes from the content, not the declared type (site_photos.py:66-69). The pixel cap and DecompressionBombWarning are turned into errors (:64-76). HEIC goes through pillow-heif (:20-27). Every image is rebuilt from raw pixels with Image.frombytes (:95), so no EXIF, GPS, XMP or ICC survives. The original bytes are never stored (only the cleaned JPEG, migration 0014:40). Photo ids are scoped to the property (find_photo :163-166). Photos are served as image/jpeg with nosniff from next.config.
- Storage: photos and generated content are in the database (site_photo LargeBinary, site_content), so nothing lives only on disk. Statement uploads store only their sha256 and parsed rows (statements.py:181-190). Invoice PDFs are rendered on request from database rows (invoice.py:131-143) and never stored.
- Owner-only access: every /site and /site/build route has OwnerDep. On a real hotel the demo subject gets 403 (tests: test_site_build.py:410-419, test_site_publish.py:321-330, 400-415). Claude is off for the demo subject and for public visitors (deps.py:22-32 with site_build.py:369-377). Limits are checked before the call (site_gen.py:700-702). No secrets are logged: only exception type names (site_gen.py:609,614), and the one-off generation script never prints the key.
- D6: _text, _caption, _points and blurbs all run site_text_ok (site_gen.py:288-363). The guard catches Unicode digits, Hindi money words, URLs and @. Photo ids must belong to this property. Prices come only from price_paise (site.py:310-317). Public payloads carry no guest data and no owner_description.
- Public routes are read-only GETs with no Claude (public_site.py). Photos have their own bucket of 240 a minute. Owner previews are sent "private, no-cache".
- Routing: a hotel host serves only "/", /_next and GETs to its own /api/public/site/<slug> (siteHost.ts:77-82, proxy.ts:104-115). The BFF refuses "..", encoded and unsafe path segments (bff.ts:43-49). Owner cookies have no Domain attribute (session.ts:86-95). The Origin check (route.ts:44, authServer.ts:56-66) blocks writes from hotel hosts. Redirects go only to slugs the API returned, or to the same origin (proxy.ts:110-126, siteHost.ts:96-105), so there is no open redirect. booking_url comes from WEB_ORIGIN on the server.
- Slugs: 3 to 40 characters, single hyphens only (so no xn-- punycode labels), the reserved list includes the app's route names, uniqueness is enforced with an IntegrityError backstop, and an old slug is held for 30 days (slug.py).
- XSS: React escapes everything. There is no dangerouslySetInnerHTML in the site components or /h. wa.me text is encodeURIComponent-encoded (siteHost.ts:113-115). The QR code holds only the API's site URL.
