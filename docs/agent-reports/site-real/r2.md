## 1. Rewriting <slug>.<root> in proxy.ts
- Host: `hostName(request.headers.get("host") ?? "")` (lib/requestOrigin.ts:8). Vercel forwards the custom-domain Host.
- Rewrite: `NextResponse.rewrite(new URL(`/h/${slug}${search}`, request.url))`. The URL bar keeps `/` (DOCS 04-functions/next-response.md:119-129), and RSC headers are propagated (proxy.md:472-476).
- Matcher: it must run on every host-relevant path, so drop the fixed list. Use `'/((?!_next/static|_next/image|favicon.ico|icon.svg).*)'` (proxy.md:636-650). Move the owner-path guard inside the function as `OWNER_PATHS.some(...)`, with the same list. Matcher values must be constants (proxy.md:136).
- Runtime: the proxy defaults to Node.js and `runtime` cannot be set (proxy.md:253-255). Read `process.env.SITE_ROOT_DOMAIN` at request time, the same way proxy.ts:12 reads SESSION_SECRET. Only `NEXT_PUBLIC_*` values are baked in at build (DOCS 02-guides/environment-variables.md:156-166). Do NOT use NEXT_PUBLIC_ for this. Client UI gets the address string from the API, so Railway needs SITE_ROOT_DOMAIN too.
- Local: the dev server already allows `localhost` and `**.localhost` origins (next/dist/server/lib/router-utils/block-cross-site-dev.js:77-78; allowedDevOrigins.md "already allows localhost, its subdomains"), so no config is needed. Chromium (Chrome and Playwright's Chromium) resolves `*.localhost` to loopback itself (well-established). Unconfirmed: Safari, and Node-side lookups (Playwright `request` fixture, curl) on macOS may not resolve `x.localhost`. In T2, use the browser page, or `--host-resolver-rules`, or 127.0.0.1 with a Host header.

## 2. Routing table (pure fn in lib/siteHost.ts, unit-tested)
Hotel roots = [SITE_ROOT_DOMAIN if set, "localhost"]. A host is a HOTEL host when it is exactly `<label>.<root>` with one label, the label matches the slug rule, and it is not reserved (www app api admin mail docs status). Every other host is an APP host: apex, www, app., *.vercel.app, 127.0.0.1, LAN IPs and unknown hosts.

| Host | Path | Action |
|---|---|---|
| app | owner paths (proxy.ts:23-45) | session guard as today |
| app | `/h/<slug>` | resolve: live = next; renamed = 308 `/h/<new>`; none = "not live yet" with 404 |
| app | `/hotel/<slug>` | 308 to `/h/<slug>` (next.config `redirects()`) |
| hotel | `/` | resolve; live = rewrite `/h/<slug>`; renamed = 308 `https://<new>.<root>/`; none = 404 page |
| hotel | `/api/public/site/<own slug>[/availability]` GET | next |
| hotel | `/_next/*`, `/icon.svg`, fonts | next (excluded by matcher) |
| hotel | everything else (`/login`, `/home`, `/h/*`, `/api/*` writes and others, `/link`) | 404 (`new Response(null,{status:404})` or a not-live rewrite) |

Booking: send hotel-host guests to the APP origin, as `${WEB_ORIGIN}/link?...`. The API should add `booking_url_base` to PublicSite so the client needs no env var. This keeps the hotel-host allowlist read-only (brief: "public and read-only").

## 3. Cookies and CSRF
- Owner cookie `seedha_owner`: `Path=/; HttpOnly; SameSite=Lax[; Max-Age][; Secure]` with **no Domain** (lib/session.ts:86-95), set at app/api/auth/demo/route.ts:29 and otp/verify/route.ts:49. It is host-only, so it is never sent to `<slug>.<root>`. That holds even with the app on the apex, because a host-only cookie on the apex does not go to subdomains.
- The theme cookie (components/ThemeToggle.tsx:31, website/SiteTheme.tsx:36) and the consent cookie (website/CookieConsent.tsx:18) are host-only too. Hotel pages need neither. Do not add Domain.
- Caveat: subdomains are SAME-SITE as the apex, so SameSite=Lax gives no protection between hotel hosts and the app host. The real guard is the BFF Origin check (app/api/[...path]/route.ts:40 using lib/authServer.ts:56-66) and the auth `guard()` (authServer.ts:168-175). Keep both. Optional hardening: in production, use the `__Host-` cookie prefix against cookie tossing from a subdomain. Hotel pages run no owner JS, so this is low priority, and the rename signs everyone out.
- The ShellProvider in the root layout loads nothing until an app-shell component asks (components/shell/ShellData.tsx:20-21), so hotel pages make no owner calls. The proxy 404 on hotel `/api/*` (except public site GETs) enforces this too.

## 4. CSP, headers and images
- The current CSP (next.config.ts:7-20) works unchanged on hotel hosts if photos are same-origin: `/api/public/site/<slug>/photos/<id>` through the BFF public rule (lib/bff.ts:17). `img-src 'self' data:` already covers a QR data URL. The BFF forwards only content-type and content-disposition (route.ts:15). Add `cache-control` (and ETag if wanted) for photos, plus a per-request size sanity check. Avoid absolute app URLs for images, which would need CSP changes per host.
- `frame-ancestors 'self'`, X-Frame-Options SAMEORIGIN: the B2 live preview must render HotelSite inline, or iframe `/h/<slug>?preview` on the APP host. It must not frame `<slug>.<root>`, which is cross-origin and blocked. Unpublished preview data must come from an owner endpoint.
- Add `X-Robots-Tag: noindex` for the not-live 404 only.
