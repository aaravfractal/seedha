# B1: site photos, storage and generation API (done, uncommitted in .worktrees/sb1)

## Files
- app/services/site_photos.py: content-sniffed upload checks, resize, re-encode, store/list/order/delete.
- app/services/site_gen.py: D6 site guard, templates, sample, limits/usage, ClaudeSiteWriter, run_generation.
- app/routers/site_build.py (registered in app/main.py); app/config.py SITE_GEN_* fields.
- tests/test_site_build.py (94 cases, Claude always a fake); scripts/site_gen_once.py (manual, never run here).

## Storage choice
Photos are LargeBinary rows in site_photo (migration 0014). One table works on SQLite and Postgres,
survives redeploys on Railway's ephemeral disk, is covered by database backups, needs no extra service.
8 x ~200 KB = ~1.6 MB per hotel. List queries defer the bytes.

## Photo pipeline
Body read capped at 10 MB + 1 (413 file_too_large). Real format by content: JPEG/PNG/WebP/HEIC (HEIC via
pillow-heif==1.8.1, owner-approved 12 Oct; its wheels are GPLv2-labelled; it applies HEIC rotation itself);
GIF/PDF/AVIF/other 415 unsupported_type; MAX_IMAGE_PIXELS 40M + DecompressionBombWarning as error (413
photo_too_large); truncated 422 unreadable_photo. exif_transpose, RGB (alpha on white), max 1024 px,
rebuilt from raw pixels (Image.frombytes) so EXIF/GPS/XMP/ICC cannot carry over, JPEG q85->60 until <=200 KB.
Max 8 per property (409 too_many_photos).

## API (all owner-only: OwnerDep; per-client rate limits 60/min edits, 240/min images, 5/min generate)
- POST /site/photos (multipart field "photo") -> 201 Photo
  Photo = {id, position, width, height, size_bytes, url: "/api/site/photos/<id>", caption_en, caption_hi}
- GET /site/photos -> {photos: [Photo]}; DELETE /site/photos/{id} -> {photos}; PATCH /site/photos/order {ids} -> {photos}
  (422 bad_order unless every id exactly once)
- GET /site/photos/{id} -> image/jpeg, Cache-Control "private, no-cache", ETag "<sha256>", 304 on If-None-Match
- GET /site/build -> Build = {owner_description, rooms: [{name, price_paise, blurb_en, blurb_hi}],
  content: {description_en, description_hi, why_book_direct_en[3], why_book_direct_hi[3], google_description_en,
  google_description_hi}, photos: [Photo], source: none|sample|claude|edited, key_configured, model,
  generations_today, daily_limit: 3, month_tokens_used, monthly_token_cap}
- PATCH /site/build {owner_description? <=2000, rooms? 1..10 {name 2..60, price_paise StrictInt 1..10_000_000,
  blurb_en?, blurb_hi? <=300}, content? (any subset; description <=1200, 3 points <=120 each, google <=750),
  captions? [{photo_id, caption_en?, caption_hi?}] <=8 words} -> Build. Owner text is not guarded (owner's own
  words). Editing content, captions or room blurbs sets source "edited"; blurbs not sent are kept by room name.
- POST /site/build/generate -> Build + {status: generated|limit_reached|offline|sample, fallback_fields, message}
  422 not_ready unless >=4 photos, a description and >=1 room.
- GET /site/gen/usage -> {runs: [{at, status, model, input_tokens, output_tokens, cache_creation_tokens,
  cache_read_tokens}] (latest 20), month_input_tokens (incl. cache tokens), month_output_tokens, month_runs,
  monthly_token_cap, generations_today, daily_limit}

## Generation
- No key or no SITE_GEN_MODEL (get_settings blanks the key for demo/public visitors in production/public mode):
  status "sample", source "sample", no call. Sample hotel gets the existing sample copy; another hotel gets
  templates from its owner's words.
- Else limits first: 3 calls per property per India day (failed calls count), monthly cap on
  input+output+cache tokens across all properties (India month). Then one call: system prompt ~110 words,
  user = "Photo id N:" + base64 JPEG per photo (cache_control on the last image block), then hotel, town,
  room names (never prices) and the owner description fenced in <owner_description>.
  output_config.format json_schema (additionalProperties false); effort "low" only for claude-haiku-5-5
  (SDK 1.12.1 supports it); max_tokens 3000 (thinking counts).
- stop_reason other than end_turn (refusal, max_tokens), API error, or bad JSON -> "offline": if the text was
  none/sample it is filled from templates (source edited, all fields listed), else kept.
- Per-field checks: lengths, 3 points, captions <=8 words, photo ids must be this property's, order applied
  only if it lists every photo once. Guard rejects ₹/Rs/INR/rupee/lakh/crore/price/tariff/fee/rate/ticket/
  cost/charge/discount/percent/%, /-, Hindi money words, any 3+ digit number (Unicode digits mapped to ASCII,
  years not excused), web addresses, any name.tld, @. A failing field falls back to a template.
- Every call stores a SiteGenRun (tokens incl. cache, model, status, fields_fallback count).

## Env
SITE_GEN_MODEL (.env.example: claude-haiku-5-5; empty = sample), SITE_GEN_MONTHLY_TOKEN_CAP (default 300000),
ANTHROPIC_API_KEY (existing).
