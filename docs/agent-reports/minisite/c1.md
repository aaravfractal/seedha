What changed (apps/api)
- `services/card_page.py` (new): verify, single-use stay tokens, card rating, private notes, Needs-you counts. `routers/card_page.py` (new, registered in main.py).
- Verify: `booking.external_ref` (any case), only `status == "stay"` rows of that hotel (direct bookings are Booking rows too, e.g. SLH0001). A number on file means a non-erased Desk consent with a whatsapp_number (never OTA data). No phone -> needs_phone; wrong digits -> not_found (same answer as an unknown reference). Stay end (check_in + nights) > business date -> not_ended. Response leaves out unset fields; when verified, `perk_code` is always present (null when no unredeemed code for that booking or guest); `room_type` only if the booking names a room. next_check_in = business date + 14.
- Stay token: 32-char random token held as SHA-256 in a `site_rating` row with source 'card' (source_ref = booking id, stars null until used). It lasts 30 min. Verifying again replaces the token. A card token never works on /public/rate, and a /rate token never works here.
- One rating per stay: `site_ratings.stay_rated` covers link, desk and card. The card page answers already_rated / 409. GET /public/rate shows `used` and POST /public/rate gives 409 already_rated once the stay is rated another way. Erasure also blanks card comments.
- Rate: 204; 409 `already_rated`; 400 `invalid_stay_token` (unknown, other hotel, replaced or expired); 422 on bad stars, comment or extra keys.
- Feedback: `SiteFeedback` (id, property_id, message, created_at, read_at). It is never public and never counted. Owner GET /site/feedback (newest first) and PATCH /site/feedback/{id} {read}; 404 for another hotel's note.
- Limits (ratelimit.py): card_verify 10/min per client, card_verify_hotel 6/min per client per slug, card_rate 10/min, card_feedback 5/min.
- Overview Needs you: `site-notes` ("Read N private notes from guests", icon inbox) and `site-ratings` ("N new ratings this week", icon star, last 7 days). Both link to href "/site".
- Migration 0018 (reversible, batch mode): creates site_feedback and changes the site_rating source CHECK to allow 'card'. The downgrade deletes card rows first. Tested up, down and up on SQLite. Reset already deletes every table except account tables, so it clears notes and ratings (tested).
- test_route_auth.py: the 3 public routes added.
