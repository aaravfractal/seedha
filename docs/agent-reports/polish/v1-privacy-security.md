## Checked and fine
- Room board: `/rooms/nights` holds no guest data. `/rooms/{night}/{room}` holds `guest_initials` only (`owner_initials`), plus `consent_id` only while `active_consent`. The room slip prints initials. RoomBoard/RoomSheet render initials only, and "Message guest" shows only with a consent_id.
- Messaging: threads are active Desk consents with a number (`get_thread`). Withdrawn and erased consents get a 404. Owner sends need an open 24-hour window and append STOP. The away text is approved by the owner and carries STOP. Seeded consents sit on Desk stays only, so no OTA contact is used (rule 4). The sample hotel always sends simulated (`get_sender`, `sender_for_property`).
- No auto-send: draft returns text only, and `/inbox/simulate` uses fixed texts that are never STOP and stays sample-only, with 10 a minute per client plus a global ceiling. Claude output never reaches a sender (rule 7).
- Invoice: owner-only, and `thread_or_404` checks property, active consent and number. The stay is limited to the same guest and property, and flagged rows are excluded unless the owner accepted them. Personal data is the guest name only, with no phone or email. GSTIN comes from Settings (the sample GSTIN is shown only to the demo login on the sample hotel). "SAMPLE" and the fictional-data line appear on the sample hotel. The filename is sanitised to `[A-Za-z0-9-]`.
- guest_memory: holds preferences and notes only (String 200, no money). `erase_consent` deletes it.
- Pro views: owner-only, with Query bounds (paise 100..Rs 1,00,000, rooms 1..200, nights 1..30, channel length, Literal property). Data is single-property, the second property is fictional, and no guest data appears. The floor scan is bounded.
- Public mode: inbox drafts use `SettingsDep`, so remote visitors get templates. No new path calls Claude outside `get_settings`.
- XSS: message bodies, notes and memory render as React text, with no `dangerouslySetInnerHTML` in inbox, owner or pro. The booking link is built by the server.
- CSP: next.config.ts is unchanged since 04b6388, before the polish build. The PDF downloads same-origin via `/api/inbox/threads/{id}/invoice.pdf`.
