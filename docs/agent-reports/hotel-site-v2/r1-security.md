# R1 Security and privacy review: Hotel Site V2 (hotel-site-v2 at eafd3b4, base deploy b1d5424)

This was a read-only review. I read the diff, CLAUDE.md section 2, docs/HOTEL_SITE_V2.md, the hotel-site-v2 helper reports and final/a1b-security-privacy.md. I ran `apps/api/.venv` Python one-liners against `app.services.site_cards` and `app.services.site_details` to time the PDF and to probe validation. I started no servers and changed no files except this report.

## Verified OK
| area | result | evidence |
|---|---|---|
| Hotel host isolation | OK | `siteHost.ts:81-88`: POST is allowed only when the path equals `/api/public/site/<own slug>/scan`. Every other non-GET/HEAD is refused. `/h-sw.js` is allowed for GET/HEAD only. Owner paths, other slugs and `/api/auth/*` still 404 (`proxy.ts:106-107`). The BFF still applies `sameOrigin` to the POST (`route.ts:48`). The scan fetch uses `credentials: "omit"` (`HotelSiteV2.tsx:81-88`). Cookies stay host-only. |
| Scan stores no visitor data | OK (see R1-7 for logs) | `SiteCardScan` holds property_id, card, day and count only (`models.py:828-839`). `ScanIn` is `extra="forbid"` with a 3-value Literal. Unpublished non-sample hotel: `find_site` -> `resolve` -> `is_public` false -> 404, so nothing is counted. Moved slug: counted for the new hotel (the proxy 308 keeps `?src`). Unknown slug: 404. |
| BFF PUT | OK | `PUT` goes through the same `forward()`: `accessFor`, Origin check, session, owner token. The API's only PUT route is `/site/details` (OwnerDep). |
| revalidateTag reachable by public visitors | OK | `revalidatesHotelSites` requires `access === "owner"`, so it only runs after a session check. Public and device calls never revalidate. See R1-3 for owner-side abuse. |
| Service worker | OK (see R1-6) | It caches only the public site JSON, fetched with `credentials: "omit"`, under a per-slug cache name. It handles only same-origin GET navigations to the hotel's own page. Every other request passes through. The offline page HTML-escapes every value (`esc`). `tel:` and `wa.me` hrefs are built from digits only. `mailto:` is attribute-escaped. The page has its own `default-src 'none'` CSP. The slug is validated by regex. The hotel page registers the worker with scope `/h/<slug>`, or `/` only on the hotel's own host. |
| XSS on the public page | OK | No `dangerouslySetInnerHTML` except JSON-LD, which escapes `<` as `<` (`hotelSiteV2.ts jsonLdText`). Owner text is rendered as React text. `wa.me` and `tel:` are built from digits. The Maps link is a fixed Google URL with `toFixed(5)` numbers. The API refuses `<` and `>` in every details string. NaN and Infinity in geo are rejected (probed). |
| Cards PDF / QR | OK | All four routes are owner-only (OwnerDep). `kind` and `card` are Literal query params. Text is drawn with `canvas.drawString`, not `Paragraph`, so reportlab markup is never parsed. `printable()` keeps cp1252 text only. The QR SVG `<title>` is `xml.sax.saxutils.escape`d. The filename comes from a validated slug. Cost: about 70 ms for `kind=all` and 35 ms for a PNG (measured), in a plain `def` (threadpool). |
| Production lock | OK | `site_content(public=True)` passes `locked` to `read_details`. In production the public JSON for the sample hotel is always `SAMPLE_DETAILS`. JSON-LD, metadata, the OG image and the offline worker all come from that public JSON, so they are locked too. The sitemap lists static paths only. The cards are owner-only and use `public=False`, so a demo visitor sees the shared sample's owner-side edits, the same exposure as A1b-12 (R1-8). |
| Headers | OK | Hotel CSP: no `unsafe-eval` in production, `frame-src 'none'`, `worker-src 'self'`, `connect-src 'self'`, `object-src 'none'`. Permissions-Policy drops the microphone on hotel pages, which closes A1b-9 for those pages. `proxy.ts` applies the headers on the hotel host. |
| Rules 1, 6, 11, no AI | OK (see R1-5, R1-9) | No new money code: rooms and packages are shown as the API prices them. Cards carry no prices. Public pages read only `/public/site/*`. No Claude call was added anywhere in the diff. |

## Findings
| id | severity | file:line | problem | concrete fix |
|---|---|---|---|---|
| R1-1 | medium | apps/web/app/h/[slug]/opengraph-image.tsx:20-21; apps/web/lib/siteHost.ts:93; apps/web/app/h/[slug]/data.ts:24-27 | **Unvalidated slugs reach the shared cache and the API.** The proxy's `hotelPathSlug` only matches `/h/<slug>` exactly, so `/h/<anything>/opengraph-image` skips the live/none check. It calls `loadPublicSite(<anything>)`, which caches a 404 entry per slug for up to a day, makes one API call per slug and renders a 1200x630 PNG (satori and resvg CPU) every time. A second path: the proxy lowercases the slug for `resolve`, but the page uses the raw `params.slug`. `/h/DEODAR-VIEW`, `/h/Deodar-View` and the other case variants (2^11 for this slug) each pass the proxy and each become a separate cache entry and a separate API call. An anonymous script can evict real hotels from the `"use cache"` store and burn API calls (see R1-2) and serverless CPU. | In `loadPublicSite`, and in `Image` and `generateMetadata` before calling it: normalise `slug = slug.toLowerCase()` and return the not-found result at once when `slugProblem(slug) !== null`, before any `"use cache"` entry is made. Also widen the proxy check to `/h/<slug>/opengraph-image` (for example `/^\/h\/([^/]+)(?:\/opengraph-image[^/]*)?\/?$/`) so unknown slugs 404 there too. On the page, redirect a slug that is not lowercase to its lowercase form. |
| R1-2 | medium | apps/web/app/h/[slug]/data.ts:29-31; apps/api/app/ratelimit.py:47 | **Every server-side hotel render shares one rate-limit bucket.** The cached fetch sends the proxy proof but no `x-forwarded-for`, so the API sees the web server's own address. Locally that is 127.0.0.1. On Railway it is the Vercel egress IP, from the Railway-added XFF. All cache-miss renders of all hotels therefore share the per-client `site` limit of 60 a minute. R1-1 and R1-3 can drain it easily. Once it is drained, renders get a 429, then `ApiUnreachable`, then status 0 and a dynamic page that loads in the browser, so SEO HTML, LCP and the OG image fall back to "Hotel". | Give the server's own cached reads their own allowance: in `rate_limited` (or `ProxyTrustMiddleware`), when the proof is valid and no XFF hop came from the BFF, use a separate bucket (for example `site_render`, 600 a minute). Or send a fixed `x-forwarded-for: render` from `loadPublicSite` and give that key a larger limit. Fix R1-1 first, since it is the cheap trigger. |
| R1-3 | low | apps/web/app/api/[...path]/route.ts:81-86; apps/web/lib/hotelSiteV2.ts:114-116 | **Any owner write invalidates every hotel's page.** `revalidateTag("hotel-sites", { expire: 0 })` runs on every successful owner write, including writes unrelated to the site (`/ask`, `/messages`, `/desk/*`, statements). On hosted production any anonymous visitor gets an owner session through Direct beta login, and `PUT /site/details` has no rate limit. A loop of writes keeps every hotel uncached, and with `expire: 0` each guest render blocks on a fresh fetch. Combined with R1-2 this degrades all hotel pages. Public visitors cannot trigger it without a session. | Revalidate only `hotelSiteTag(<this property's slug>)`, and only for site-affecting paths: `site/*`, `rooms*`, `pro/*` branding, `demo/reset`. Skip it when the writer is the demo subject in production, because the sample's public page is locked and cannot change. Optionally add `rate_limited("site_edit")` (for example 30 a minute) to `PUT /site/details`. |
| R1-4 | low | apps/api/app/routers/public_site.py:168-174; apps/api/app/ratelimit.py:52 | **Scan counts can be inflated with no browser.** The Origin check only binds browsers. A script without an Origin header can POST scans for any published slug, or for the sample, at 30 a minute per client (about 43,000 a day from one address), up to 600 a minute across all clients. The all-client ceiling is shared by every hotel, so one actor can also block real scans for all hotels. The counts have no integrity signal. | Key the limit per (client, slug), for example 3 a minute, since a real guest scans once. Add a per-hotel daily cap (for example 500 per card per day) in `record_scan`. Label the owner view "approximate". |
| R1-5 | low | apps/web/lib/hotelSiteV2.ts:137-176; apps/web/app/sitemap.ts:34 | **Rule 11: the sample hotel's JSON-LD is not labelled.** The structured data says `Hotel` "Hotel Deodar View" with a real Mussoorie street address and geo, and the sitemap asks crawlers to index it. Search engines may show a fictional hotel as a real place. The page and the OG image say "Sample", but the JSON-LD does not. | When `site.sample` is true, either omit the JSON-LD and set `robots: { index: false }` in `generateMetadata`, or add `description: "Sample hotel. All details are fictional."` and drop `address`, `geo` and `streetAddress`. |
| R1-6 | low | apps/web/public/h-sw.js:21-24, 120-131 | **Stale owner contact in visitors' browsers.** The offline worker keeps the site JSON (owner phone, WhatsApp, email, address) and refreshes it only after a successful page load more than a day old. If the hotel unpublishes (404) or the owner removes a contact, `saveSite` skips the non-OK response and the old copy stays, so the offline page keeps showing details the owner withdrew. The worker is also never unregistered. | In `saveSite`, delete the cache entry when the response is 404 or 410. When `res.ok`, always replace the entry. Refresh on every successful navigation, which costs one small GET, instead of once a day. On a 404 navigation, call `self.registration.unregister()`. |
| R1-7 | low | apps/api/railway.json:7; docs/HOTEL_SITE_V2.md item 5 | **"No IP" is true for the database, not for logs.** The scan POST, like every request, is written to uvicorn's access log and to the Vercel request log with the client IP and the slug. The brief and the code comments say "no IP". | Say "nothing about the visitor is stored in the database; hosting logs keep request IPs for their normal retention" in the privacy page, docs and docstrings. Or run uvicorn with `--no-access-log` in production. |
| R1-8 | low | apps/api/app/routers/site_details.py:69-74, 125-145 | **The shared sample's details and cards are editable by any demo visitor**, the same exposure as A1b-12. On hosted, any Direct beta visitor can `PUT /site/details` for the shared sample hotel, including someone else's phone number, email or arbitrary text. Every other demo visitor then sees it on the owner Site screen and in the downloaded cards PDF and QR, whose text is printed from `public=False` data. The public page stays locked (verified). | In production, for the demo subject, either refuse `PUT /site/details` the way `PUBLISH_GUARD` does, or build the cards from `read_details(..., locked=True)` so downloads always use the fixed sample facts. Keep "reset before judging" in the checklist. |
| R1-9 | low | apps/web/components/site/v2/HotelSiteV2.tsx:215, 359-362; components/site/v2/copy.ts:16 | **The page promises a perk nobody set.** Anyone who adds `?src=card-*` sees "enjoy a returning-guest perk", but no perk or code exists behind it and the owner never approved this wording. This is not a lower rate (rule 6 holds), but it is a guest-facing promise without owner approval (in the spirit of rule 7) that a guest may try to claim at the desk. | Show the ribbon only when the owner has set or approved a perk text on the Website screen, and use that text. Otherwise use neutral copy such as "Welcome back. Book your next stay directly here." |
| R1-10 | low | apps/api/app/services/site_details.py:79-90, 148 | **Validation gaps (owner-only input).** (a) `no_markup` allows control characters (NUL, newlines in single-line fields) and bidi or zero-width characters: U+202E and U+200B were accepted, so a one-character invisible `name_en` passes `min_length=1`, and display text can be spoofed. (b) `phone_ok` uses `str.isdigit()`, which accepts superscript and Arabic-Indic digits (`²³⁴⁵⁶⁷` and `١٢٣٤٥٦` were accepted). The shown number then differs from the `tel:` link, which is empty because JS `\D` keeps only ASCII digits. (c) The email pattern allows `?`, `&` and `=`, so `a@b.c?cc=x&body=hi` is accepted and becomes extra `mailto:` parameters. None of these are XSS. | Reject `unicodedata.category(c) in {"Cc","Cf"}` except a plain space in every PlainText field, and require at least one letter or number after stripping. Use `re.fullmatch(r"\+?[0-9 ]{6,16}", value)` for phones. Tighten the email to `^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}$`. |
| R1-11 | low | apps/api/app/routers/site_details.py:125-190 | **The cards and QR routes have no rate limit.** At about 70 ms of CPU per PDF in the threadpool they are cheap, but on hosted any anonymous demo session can call them in a loop alongside the other unthrottled owner routes (compare A1b-1). | Add `dependencies=[Depends(rate_limited("cards"))]`, with `"cards": Limit(20, 60)`. |
| R1-12 | low | apps/web/lib/hotelSiteV2.ts (hotelPageHeaders) | **The CSP still allows `'unsafe-inline'` for scripts on public hotel pages**, inherited from the app policy. Today every owner string is React-escaped and the JSON-LD escapes `<`, so I found no injection, but the CSP gives no second line of defence on the most public surface. | Later: a nonce-based `script-src` (`proxy.ts` can mint a nonce per request for `/h/*`). The cost is that a nonce makes the page dynamic, so weigh it against the static-per-hotel goal. At minimum, keep this listed as accepted risk. |

High: none. Medium: R1-1 (unvalidated or case-variant slugs fan out into cache entries, API calls and OG renders) and R1-2 (all server renders share one per-client API bucket). The rest are low.
